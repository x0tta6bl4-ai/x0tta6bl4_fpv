# Правила для всех ИИ-ассистентов (Claude, GPT/Codex, Gemini/Antigravity, Grok/Cursor)

Этот файл — общий договор. Его читают все четверо. Роли и зоны ответственности — в `docs/ROLES.md`,
порядок работы с git — в `docs/WORKFLOW.md`, устройство проекта — в `docs/ARCHITECTURE.md`.

## Что это за проект

FPV Anatomy — интерактивный учебник по книге «FPV-дрон: понять, а не зазубрить» (редакция 7).
Одна HTML-страница: 21 глава (0–20), приложения, у каждой главы стенд с заданиями.
Главное правило стендов: **сцена учит действовать в реальной ситуации**, а не украшает.
Ученик должен понимать, что и зачем он делает, и не проходить задание перебором.

Пользуются в основном **с телефона** — всё проверяем сначала на ширине 360–412 px.

## Как общаться с владельцем

- Пиши по-русски, просто и по делу (ELI18): сначала итог, потом что сделано, что не сделано и почему.
- Не придумывай факты и цифры. Если не проверено — так и скажи.
- Не проси присылать пароли, токены и ключи в чат.

## Жёсткие запреты

1. Не менять и не коммитить `data/book-pages.json` и `data/book-images.json` — это исходный текст и сканы книги,
   репозиторий публичный. Не убирать их из `.gitignore` и не вставлять текст книги дословно в другие файлы.
2. Не добавлять военное/ударное применение, оскорбления, реальные имена и позывные.
3. Не коммитить в `main` напрямую — только через Pull Request (см. `docs/WORKFLOW.md`).
4. Не оставлять PR с упавшими тестами: `npm test` должен закончиться строкой «Всё прошло.»
5. Не указывать названия и версии ИИ-моделей в коммитах, PR, коде и тексте учебника.
6. Не трогать чужую зону без договорённости (зоны — в `docs/ROLES.md`; CI-проверка `zones` это ловит).
7. Не ослаблять и не удалять существующие тесты, чтобы PR стал зелёным. Тест упал — чини код или напиши в PR,
   почему тест неверен. Не получается сделать задачу честно — так и напиши: «не сделано, потому что…» — это нормальный итог.

## Как работать с задачей

1. Начало: прочитай свою карточку в `docs/tasks/`, `git log --oneline -10` и `git status`. Чужие незакоммиченные правки не трогай.
2. Одна задача — одна ветка — один PR. Не берись за соседние задачи «заодно».
3. Перед PR: `npm run zones` и тесты (ниже). В описании PR — что сделано, что проверено (вывод тестов), что не сделано.
4. Конец: обнови в своей карточке статус и раздел «Журнал» (2–5 строк: что сделано, что осталось, на чём остановился),
   чтобы следующая сессия — твоя или другого ассистента — продолжила без пересказа.

## Правила содержания

- Каждое утверждение — из книги или из официальной документации (Betaflight, ExpressLRS). Расхождение
  книги с документацией не «исправляем молча», а отмечаем блоком «Уточнение» и записываем в PR.
- Числа с метками: «закон», «оценка», «зависит от версии», «пример».
- Термины объясняем при первом появлении. Без канцелярита и воды.
- **Не разрастаемся** (обсуждение 004, П8). Новая *видимая* фраза в главе (не в «Подробнее» и не в свёрнутом блоке),
  которой нет ни в цитате `where` карты среза (`docs/content/srez-coverage.json`), ни в действии полевого чеклиста, —
  находка ревью «стоит поправить». Номер среза рядом её не оправдывает. Выход — перенести в «Подробнее» или заменить
  уже существующую фразу. В PR пишем: какое умение даёт добавленное и что заменено или свёрнуто.
- **Мораторий** (обсуждение 004, П1): до итогов пилота гл. 10 новых стендов, вкладок, тренажёров и блоков в главы
  не добавляем; исправления ошибок и работы по карточкам 041–044 — можно.

## Правила стендов (сцен)

- Сцена открывается целиком в рамке; номера деталей скрыты; касание детали показывает её описание.
- Подсвечено только то, что относится к текущему шагу/заданию; постоянные «украшения» запрещены.
- Ученик сам делает вывод, ошибка объясняется («почему нет»), а не просто «неверно».
- Для процедур (диагностика, настройка) — пошаговый разбор с панелью (`meta.proc`, см. `src/figs/armcase.mjs`).
- Цвета только через токены CSS (`--accent`, `--ok`, `--bad`, `--warn`, `--anatomy-*`); проверка в светлой и тёмной теме.
- Линии подсветки тонкие (не толще 1–1,2 в единицах рисунка).

## Проверка перед PR

```bash
npm install                  # один раз
npx playwright install chromium   # один раз (на Windows тоже)
npm test                     # сборка + 19 автотестов, ~15 мин
```

Если меняешь стенд — добавь или обнови его блок в `tests/missions.mjs`.
Если меняешь только тексты — минимум `npm run build:dev` и `node tests/run-all.mjs routes width`.
