## Парные короткие и полные правила

В каждом из шести разделов первое предложение «Коротко» связано с полным объяснением этого же раздела. Машиночитаемые соответствия — `short_rule_pairs` в реестре. Итог главы сохраняет существенные ограничения из этих пар: химия, условия напряжения, паспортный ток, необходимость подтверждения причины.

Это результат авторской проверки. Независимому ревьюеру: сравнить короткую и полную строки по смыслу, особенно возможность ошибочного выбора режима заряда. Наличие пары в JSON не доказывает её корректности автоматически.

## Данные для инженера сцены

Файл `ch06-cases.json` содержит две причины и три явных случая (показанный A, с подсказками B, самостоятельный C); ENTRY отделяет посадку от диагностики. Он содержит предложенный контракт `STEPS`, `CAUSES`, наблюдения `evidence`, варианты `fix` и отдельные `postfix_checks`.

- `temperature`: ранняя просадка — улика; подтверждение появляется только после сравнимого температурного контроля.
- `cell_count`: независимый прибор подтверждает общее напряжение; несоответствие физического S настройке подтверждает отдельную причину. Нет данных нагрузки — нет вывода о якобы измеренной просадке.
- Числа помечены как учебные примеры. Они не являются записью настоящего борта, рекомендацией нагрева или универсальными порогами.
- Первый вариант `fix` — авторское обозначение верного ответа. В интерфейсе его позицию надо перемешивать. Звезда требует проверки результата.
- Группы геометрии и адаптер данных связывает инженер. Файл не подключён к приложению и не объявляется готовой сценой.

Обсуждение формата и интеграции продолжается в PR задачи 008; готовность контракта не означает согласие инженера с каждой деталью формата.
