# 002. Образец: Learn Arduino — что взять, что не брать

Разбор сайта [Learn Arduino](https://learn-arduino-red.vercel.app/) (владелец, через Chrome, 2026-10-21; 3D-сцену в работе
не видел — WebGL был выключен, устройство проверено по коду). Записано Claude для обсуждения «Верстак сборки».

## Как устроено
- Один рабочий стол: в центре плата и компоненты; справа вкладки «Обзор / Подключение / Объяснение кода / Характеристики»;
  под ними пример программы и монитор сообщений; снизу лента из 11 уроков (плата → светодиод → кнопка → датчики → мотор → проект).
- **Один параметр — в нескольких местах сразу:** выбрал компонент — открылись его настройки и подсветились связанные значения
  программы; изменил значение — обновились код и симуляция; при исполнении подсвечиваются строки программы.
  Ученик видит цепочку «что изменил → где используется → что получилось».
- Техника: обычный JS + DOM, Vite, three.js r186 (WebGL2), детали строятся программно, отдельные заранее написанные модели
  уроков (произвольный Arduino-код не компилируется — «Compiling/Uploading» имитация), прогресс в `localStorage`, адреса `#blink`.

## Слабее как учебник
1. Зачёт — за успешный запуск, понимание не проверяется.
2. Без WebGL практика не запускается (обработчик «Run» выходит, если сцены нет), хотя обещано обратное.
3. На телефоне сцена → уроки → объяснение → код по вертикали: действие и отклик расходятся.

## Что уже перенесено
- Урок LOW V (гл. 6): показания приборов и расчёт среднего (среднее = общее ÷ S) — прямо в карточке шага, рядом с выбором
  вывода; приборы на сцене и в карточке совпадают (тест `tests/lowv.mjs`). Условия зачёта остаются нашими: подтверждённая
  причина + исправление + контроль.
- 3D-модель гл. 3 при отказе WebGL показывает текст и отсылает к плоской схеме (не блокирует главу).

## Идея «Верстак сборки» (после результата пилота LOW V)
Ученик сам собирает дрон: слот → деталь из списка, площадка A → площадка B (провод); настройка Betaflight как «код»;
подача питания через smoke stopper → бинд → арм → моторы → видео. Ошибка — реальное последствие с объяснением.
Дорожка 10–12 уроков по шаблону пилота. Первый пробный урок — «подключи приёмник к полётнику».

### Позиция Gemini (мобильная эргономика, тач-взаимодействие и доступность)

**W1. Тач-соединение контактов без перетаскивания (Tap A → Tap B).** На мобильном экране 360 px контактные пятаки полётника имеют физический размер 1–2 мм; жест drag-and-drop закрывает пальцем целевую площадку и приводит к ложным броскам провода. Решение: двухшаговый тач. Первое касание контакта (или площадки на приёмнике) выделяет его и расширяет активные совместимые тач-зоны до $\ge 44 \times 44$ px с визуальным ореолом; второе касание прокладывает провод нужного цвета. Проверка: замер `getBoundingClientRect()` активных контактных мишеней в тесте `phone.mjs` $\ge 44 \times 44$ px, ноль ложных срывов при тач-эмуляции.

**W2. Докинг схемы платы вверху экрана (Docked Viewport $\le 40\%$ vh).** Learn Arduino на смартфоне выстраивает всё в длинную вертикальную колонку: чтобы увидеть реакцию на плате после нажатия кнопки, ученик вынужден постоянно скроллить вверх-вниз на 400–600 px, теряя связь «действие → последствие». Решение: интерактивная схема верстака прилипает к верху экрана (высота до 38–40% вьюпорта), а карточка активного шага сборки (выбор провода, переключатель пинов, кнопка пайки/проверки) прокручивается снизу. Проверка: расстояние между активным органом управления и зоной индикации на плате в тесте не превышает 320 px; замер числа скроллов при выполнении урока на телефоне равен нулю.

**W3. 2D SVG-распиновка как автономный первичный движок (без зависимости от WebGL).** На эталонном сайте Learn Arduino практика полностью блокируется при отключении WebGL (проверено владельцем). Для «Верстака сборки» 2D векторная интерактивная схема (pinout diagram) должна быть полноценным первичным движком со стандартной цветовой кодировкой проводов (красный 5V/VCC, чёрный GND, белый/жёлтый TX/RX, зелёный SBUS/IBUS, синий Video/SmartAudio). 3D-модель платы должна служить лишь вспомогательным обзорным слоем. Проверка: тест при `WebGL = null` проходит 100% шагов сборки и диагностики без ошибок.

**W4. Непосредственный физический отклик без модальных окон.** При ошибке монтажа (переполюсовка XT30/XT60, короткое замыкание 5V на землю, перепутаны TX/RX местами) ученик должен видеть реальную реакцию прямо на схеме: красный светодиод smoke stopper вместо зелёного, дымок/нагрев компонента при подаче прямого питания, отсутствие ответа в CLI при перепутанном UART, с обязательным объяснением физической причины в карточке шага. Проверка: тест сценариев сборки проверяет наличие наглядного визуального индикатора поломки и обучающего комментария для каждой возможной ошибки подключения.
